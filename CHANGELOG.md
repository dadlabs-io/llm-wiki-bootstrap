### `/wrap-up --auto-commit` / `--auto-push`, and a closing line on every wrap-up (task #51, the user's ask)
- **Why**: the user closes a session's window when the wrap-up is done, and had no way to know it was safe: the wrap-up committed only the notebook's promote, never pushed, and ended on a summary that looked the same whether work was saved or not. The denial check counts the read-guard's blocks apart, as the wiki-cycle suite does.

### The gate checks every `>` quote against the raw (task #47, from agent-builder's ingest-fidelity handoff; frontmatter spec v12)
- **Why**: agent-builder checked six entries from the 2026-09-23 batch (four sonnet `wiki-ingester` workers) against their full sources. All six had errors, and each worker had scored its own extraction fidelity 3.5–5. The pattern across all six: quotes spliced in reverse order, reworded, changed inside the quote marks, and once a phrase that is nowhere in the source. Nothing in the pipeline compared a `>` line with the raw.
- **Change**:
  - `_entry_checks.py` gains `check_quotes()` and `read_raw_text()`.
  - **What is compared.** Every double-quoted span on a `>` line; a line with no quote marks is compared whole, minus a trailing ` — attribution`.
  - **How.** `...`, `…` and a `[bracketed insertion]` split a quote into pieces, and each piece must be in the raw, in the raw's order. The comparison runs on word tokens with case, punctuation, line breaks, HTML entities, transcript timestamps and speech fillers removed. That is what lets a quote from an auto-caption transcript (`"have\n\nn't"`, "uh") match, while a changed word or number does not.
  - **What is skipped.** Pieces under four words (labels); callouts (`> [!note]`); fenced code; PDF and image raws.
  - **What raws are read.** A folder raw is read whole. A notebook's printed outputs count.
  - **Result.** Warnings, never a refusal: worded differently, not found (a wrong quote, or a raw that lacks the passage), out of order.
  - Both callers pass the raw: the `wiki-update.py` gate and the mechanical lint's backlog view.
- **Proven**: `tests/scripts/test_quote_check.py`, 27/27, including the gate filing with the warning and the lint reporting it. With `check_quotes` disabled, the 6 checks that need a quote to be caught fail. Over agentic-design's 1,228 entries with a text raw it runs in 6 s.

### `-C` is a fixed ceiling of 120; `--depth-check` measures whether C ever cut, and can now fail (tasks #38, #39)
- **Why**: tracing the search against qmd 2.8.3's source (`store.js` `hybridQuery`) found that every keyword and vector list is fetched with a hard-coded 20, the lists are fused, the fused set is sliced to `candidateLimit`, and one chunk per remaining document is reranked. So the reranker's pool is at most 20 × the number of lists (five when the query expands: about 100), whatever C is. Measured with `-C 500`, so nothing truncated: 77 candidates in agentic-design (1,211 files), 36 in agent-builder-bootstrap, 39 in llm-wiki-bootstrap. The 8%-of-files rule (40–200) therefore never bound: agentic-design's sized C of 100–110 sat above its pool of 77. Its floor of 40 was the only part that could cut, and did: on 2026-09-13 C=40 missed entries C=100 found because 40 < 77, not because the notebook had outgrown 8%. The two small notebooks sit just under 40 and would have crossed it as they grew.
- **And the depth check could not fail**: it compared C with 2C, but when neither binds both runs rerank the identical pool, so it reported "0 missed — C is enough" every time. A green that cannot turn red.
- **Change** (`wiki-qmd-query.py`):
  - `-C` defaults to a constant 120 (`$WIKI_QMD_C` still overrides), above every measured pool. The sizing function and its constants are gone. Same behaviour as before on every notebook today, and no floor left to cross later.
  - Every search logs qmd's own count of candidates reranked (its "Reranking N chunks" progress line, which the wrapper used to discard) and prints it in the status line. `--stats` reports the median and max against C, leaving out `--depth-check`'s own calls.
  - `--depth-check` searches sampled titles and reads that count against C: exit 0 with the headroom when C was never reached, **exit 1** when any search reached C ("raise C"), **exit 2 "not checked"** when no search produced a count. It never reports green over nothing measured.
  - The slot, retry and timeout loop moved into one `run_search()` used by both the search and the depth check.
- **Proven**: a real search reranked 77 of 120 on agentic-design, the number measured by hand before the change. `--depth-check` on 4 sampled titles: 35–76 of 120, exit 0, headroom 44. The same with `-C 30`: every query "30 of 30 REACHED C", exit 1. With the search stubbed to produce no count, and to time out: "not checked", exit 2. `/wiki-search` suite: see below.

### `qmd query` hang root-caused: Vulkan fallback without a CUDA runtime; CUDA preflight added; truth-status filter fixed
- **Root cause, measured**: `qmd query` runs three bundled GGUF models in-process through node-llama-cpp (Ollama is not involved). With no CUDA runtime installed it fell back to Vulkan across an RTX 4070 + Intel iGPU, where token generation never returned (model loads in 2 s, a 60-token generation ran past 118 s), so every never-seen query hung at the expansion step at 100% CPU on all 32 cores; repeat queries only looked fine because expansions are cached. Four parallel ingest workers each running it locked the machine (11 stalled processes killed). CPU-only (`QMD_LLAMA_GPU=false`) generated but node-llama-cpp reported zero math cores and reranking six chunks exceeded 120 s.
- **Fix**: the CUDA 13.2 runtime — `winget install --id Nvidia.CUDA --version 13.2 --exact --override "-s cudart_13.2 cublas_13.2"` (runtime + cuBLAS only; 13.1+ toolkits no longer bundle a driver; node-llama-cpp's prebuilt CUDA binary needs 13.1+). After it: `gpu=cuda`, 24 math cores, the hung generation takes 0.8 s, a fresh full `qmd query` runs in 16 s. Shells opened before the install lack the CUDA PATH until restarted.
