## TL;DR — the 4 commands

- **`/wiki-cycle [flags]`** — universal orchestrator (90% of wiki work)
- **`/wiki-update <url(s)>`** — single = fetch now; multiple = batch-queue
- **`/wiki-search <query>`** — read
- **`/wiki-init <topic>`** — one-time scaffold

## Folder conventions

The framework doesn't prescribe a folder taxonomy — invent one based on your topic. Some shapes that work:

- **Research-heavy topics**: `papers/`, `tools/`, `patterns/`, `benchmarks/`
- **Practical-craft topics**: `recipes/`, `techniques/`, `equipment/`, `references/`
- **Code-stack topics**: `patterns/`, `libraries/`, `gotchas/`, `benchmarks/`
- **Build / project topics**: `concept/`, `regulations/`, `vendors/`, `locations/`

`/wiki-update` will prompt if a folder doesn't exist yet. Each folder gets its own `README.md` (one paragraph) explaining its purpose; _MAP.md picks that up automatically.

## Auto-maintained files (don't hand-edit)

These are regenerated by cycle scripts — edits get overwritten:
- `_MAP.md` (regenerated by `wiki-map-compile.py`)
- `<folder>/_INDEX.md` (regenerated by `wiki-index-per-folder.py`)
- `<entry>.md` `<!-- BACKLINKS-AUTO -->` sections (regenerated by `wiki-reciprocate-backlinks.py`)
- Top-level `_INDEX.md` at topic root (regenerated by `wiki-index.py`)
