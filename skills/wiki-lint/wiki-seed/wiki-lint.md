# wiki-lint — skill

A health check on the wiki, available at two depths. The default pass is a fast deterministic script that catches mechanical rot: links pointing at files that no longer exist, pages nothing links to, half-finished TODO text, missing frontmatter. The `--full` pass goes further — the agent reads every entry and looks for the problems a script cannot see, such as two entries contradicting each other. Neither mode changes anything on its own; the full mode applies only the fixes you approve.

**Trigger:** */wiki-lint* — also "lint the wiki", "wiki health check", "check the wiki for issues". For the deep pass: */wiki-lint --full*, "semantic lint", "find contradictions", "find missing connections in the wiki".

**Input / Output:** Reads the entries under `wiki/` (not `sessions/`, task cards in `tasks/`, or the generated `_INDEX.md` / `_MAP.md`). The mechanical mode prints its report and saves it to `_inbox/reports/lint-report.md` (`_inbox/` sits beside `wiki/` at the notebook root). It covers:

- broken links, live `[[wikilink]]` syntax the link checker cannot follow, and orphan pages (a retired entry is not an orphan; a page meant to stand alone, such as the wiki's HOME, says so with `standalone: "<reason>"` in its frontmatter and is listed apart with that reason)
- stale "pending" notes of our own: "pending ingestion" or "awaiting fetch" in any entry; "not yet built" or a `TODO:` marker in our own (tier `self`) entries only, since in a research entry those words are usually the source describing its own plans. Quotes, code, links and frontmatter are skipped
- frontmatter: required fields; valid `tier`, `confidence` and `ingested_by` values; tags and lifecycle dates present; dates in `YYYY-MM-DD` form, `source_url` an `http(s)://` or `internal://` address, and no `verified: verified` that `/wiki-verify` did not record (the frontmatter spec ([wiki-frontmatter-best-practices.md](../../../wiki/project/best-practices/framework/wiki-frontmatter-best-practices.md), in the global toolset) defines them all); and frontmatter that would not parse, checked on the entries and on the installed skill and agent files, since a skill whose frontmatter does not parse never triggers
- `raw_path` resolving to a real file or folder; a tier `self` entry has none and counts as self-authored
- code drift: a `project/` entry that names the code it describes (`describes: <path>` or `<path>@<commit>`) is listed when that code changed since the pinned commit or after the entry's `last_reviewed` day, including uncommitted edits. The path is relative to the project's repo, which a notebook names as `project_root` in the notebook registry; a wiki inside its project uses the project folder. A broken path, an unknown commit, or a notebook with no repo is listed too. It is a prompt to re-read the entry, not a failure: re-read, correct if needed, then bump `last_reviewed` and pin the current commit
- living pages behind their notes: a living page (one marked `kind: living`, or any page under `project/architecture/` or `project/components/` not marked another kind) is listed when a decision, code-change or troubleshooting note links to it, or is linked from it, and the note is dated after the page's `last_reviewed` (else its `date`). The note may have changed what the page describes: read each note, rewrite the parts of the page it makes untrue, then set `last_reviewed` to today; a backlink line is not a revision. Warn-only. `/wrap-up` reads this section and the code-drift one for living pages at the end of every session
- the truth-status and lineage fields (`verified`, `type`, `revises`, `contradicted_by`, and the like)
- retirement links: a retired entry's `superseded_by` must name a real entry (a path, or a bare slug), and that successor must name the retired entry back, a link or its slug, so either page leads to the other. A note such as "(none yet)" in `superseded_by` is listed too, since any value retires the entry and hides it from search
- renamed terms: when the project renames something, the old and new names go in a table at `_config/renamed-terms.md` (beside `wiki/`), one row per old name (`| Old name | New name | Since | Note |`), so several old names can point to one new name. The lint lists every page of ours (tier `self`, or anything under `project/`) that still uses an old name, as a whole word in any case, and names the new one. Decision entries are skipped, since they record the names used at the time, and so are quotes, fenced code blocks, link targets and frontmatter (a backticked name in a sentence is checked). With no table the report says the check did not run
- hubs behind their tag: a hub page (one that gathers a topic from across folders, such as agentic-design's Obsidian hub) names the tag it collects with `hub_tag: <tag>`; every live entry carrying that tag that the hub does not link yet is listed under it, and `/wiki-cycle` adds the missing lines after an ingest
- search-index coverage: files the search index holds against `.md` files on disk
- the body checks shared with the ingest gate: a TL;DR, a Related section with at least two wiki links (a warning for tier `self`), the entry layout (body, then the Source/Raw footer, then the auto backlinks block), three or more tags, `stub` on thin entries, and numbers on `>` blockquote lines rather than in prose (except on a living page, which states its own figures; and a quote check that skips a one-line forward pointer such as `> **Superseded by:** [page](page.md)`). Here they only warn: they show the backlog in existing entries, while the gate refuses a new entry that breaks a hard rule (TL;DR, Related, layout, or frontmatter that would not parse). Hub, system and framework-contract pages and retired entries are exempt.
- task cards, in a project that keeps one card per task (`wiki/tasks/` with `tasks/ORDER.md`): the cards are not entries, so none of the checks above apply to them, though a link to a card still resolves. Instead the report gives a Task cards section listing every break of the cards' six rules (each current card in `ORDER.md` exactly once, every listed number has a card, numbers unique, required fields set, a waiting card says what it waits on, the next number above every card)

The run exits 0. With `--strict` it exits 1 on broken links, an invalid truth-status or lineage field, an out-of-range `ingested_by`, or a broken task-card rule. In either mode it exits 3 when part of the run checked nothing: no entries were found, the search index is missing, does not hold this wiki or is empty, or no installed skills were found. The report then opens with "NOT FULLY CHECKED" and names each part, so an empty section is never read as a clean one.

The full mode runs the mechanical pass first, then additionally writes `_inbox/reports/<agent>-semantic-lint-<date>.md`, evaluating every entry against six criteria — contradictions, missing cross-references, thin coverage, concept gaps, tier accuracy, and a catch-all — plus a drift-watch section for entries you have flagged as needing a deep comparison against a named canonical source. It ends with the link-gap pass (2026-10-23): every entry with fewer than two curated links (under Related, See also or Cross-references), and every entry filed since the last pass, gets the full search on its title and TL;DR, and each result that is another entry, scored 0.45 or more and not already linked either way goes on a review sheet, `_inbox/reports/link-gaps-<date>.md`. Session pages, task cards, HOME and hub pages and framework-contract docs are never suggested. Nothing is linked until you tick a pair (`- [x]`) and run the sheet's `apply` line, which links each ticked pair both ways in the Related section. A search score is a pointer, not a verdict: on agentic-design the search alone kept 421 old auto-added links where a reader kept 43, so tick only pairs about the same subject.

**Works with:** [`wiki-cycle`](./wiki-cycle.md) runs both passes as cycle steps, and [`wiki-report`](./wiki-report.md) pulls the lint counts into its summary. [`wiki-promote`](./wiki-promote.md) re-runs the mechanical pass after promoting entries, to confirm the move left no broken links.

**Note:** The full mode reads every file in the wiki, so it costs real time and tokens — that is why it is not the default. Findings are never auto-applied: you approve the fixes, then the mechanical pass re-runs to verify nothing new broke.
